# TOARU / 幻想收束 · 单机试玩

独立于 Python / QQ 机器人的纯浏览器试玩版，可发布到 GitHub Pages。网页运行时不需要 Python、数据库、机器人账号或服务器。

## 已实现

- 794 张公开卡牌：常规单抽、十连、150 抽 FES 保底。
- 盲盒招募：逐个开启、全部开启、黑色盲盒和星级突变。
- 卡册：名称 / 卡牌 ID 搜索、星级 / 类型筛选、重复卡计数。
- 配队：6 个战斗位、6 个辅助位，支持编入与移除。
- 初始 30,000 呱太、每日签到、可重复领取的试玩补给。
- 浏览器自动存档、JSON 导入 / 导出、确认后重置。
- 适配手机与桌面，支持键盘操作和减少动画偏好。
- 参考录像的招募演出：原版呱太图标 / 显示屏、剪影揭晓、属性铭牌、星级动效、三星彩虹光圈和立绘运镜。
- 演出支持跳过、关闭和免费重播。声音、简化演出、1× / 2× 与暂停控件在连续抽卡稳定性验收完成前暂时锁定。
- 原版 19 秒追猫过场（含原音轨）、三星角色原版前摇（含台词与音效），以及普通角色揭晓音效。

暂不包含战斗引擎、排行榜、多人共斗、QQ 账号关联、云存档或充值。配队仅用于保存阵容，不计算战力。

## 本地启动

需要 **Node.js 24 或更新版本**。在仓库中的本目录执行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。首次启动会从本目录 `assets/cards/` 和 `assets/gacha/` 的公开资源源生成 `public/` 运行资源；生成图片与 `node_modules/` 不提交。

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`npm run build` 生成 **`dist/client/`**，并检查静态资源、元数据与发布包内容。`npm run preview` 只提供该静态目录，默认地址是 `http://127.0.0.1:4173/IFfanclub/`，可验证网页不依赖 Python 或后端。

当前仓库根目录就是独立网页版根目录；源码、构建脚本和全部必要资源均在其中。复制本仓库后安装依赖即可构建，不依赖原 `ifbot` 工作树、机器人源码、素材提供者磁盘或参考录像。要移动一个无需重新构建、可直接托管的版本，只复制构建后的 `dist/client/`。请通过 HTTP(S) 访问，不要双击 HTML 使用 `file://`。

## 招募动画与素材

招募后先播放原版追猫过场，再点击显示屏上的呱太图标逐位揭晓。声音默认开启，播放视频原音轨、对应背景音乐和从参考录像恢复的原版揭晓音效；可以随时点击「声音：关」。关闭后可从「本次相遇 → 继续演出 / 重播演出」进入。跳过过场只进入图标屏幕；跳过全部会立即揭晓本轮剩余盲盒；直接关闭不会替你打开其余盲盒。角色和扣费在招募时已保存，演出与重播不产生新抽卡。

音画同步、暂停和 2× 倍速逻辑仍保留在实现中，但相应控件目前锁定，等待连续抽卡稳定性验收后恢复。浏览器阻止首次自动播放时会显示手动播放入口。

参考用户提供录像中的三个段落：

- 约 26–30 秒：显示屏、十个图标按约 0.22 秒间隔淡入、反光与彩纸，不做弹跳入场。
- 约 31–34 秒：普通卡点击后直接切入左侧剪影、斜向铭牌与空白显示屏，经过白场亮相后自动淡回图标屏，不再放大呱太蓄力或等待「下一位」。
- 约 55–72 秒：三星彩虹光圈、白场、两侧特写交叉淡化、拉远、铭牌和三星落位，随后自动返回。暂用 cutin 代替宽幅场景：拉远后完整显示原图，两侧用同图放大、模糊并压暗补齐，不叠加彩纸。缺少对应角色台词数据时不显示替代台词，也不使用卡牌称号冒充台词。

现在是 **原版通用视频 + 2D 角色揭晓**，不是原版动画引擎移植。通用视频按参考录像的六个分镜顺序拼接，保留原音轨；不同猫数量、碎屏等分支暂未接入，也没有臆造这些分支的触发概率。角色揭晓仍使用方形 cutin 的平移与缩放，三星全景采用完整原图加模糊侧边的临时方案，未接入完整的全身立绘、宽幅场景和角色语音，不能达到逐帧一致；未用技能宣传片冒充招募揭晓。三星运镜以录像中的辅助角色为参考，尚未逐角色验证。通用过场提供文字画面说明，原声暂缺逐字字幕。减少动画模式直接展示角色，由用户返回图标屏。

两首背景音乐通过与参考录像比对选择。视频加载失败或较慢时仍可跳过，不会丢失已保存结果。后台切换和连续第二次抽卡的媒体生命周期仍需真实浏览器验收。

新增的浏览器媒体保存在 `public/media/`，共约 14.5 MiB，来源与转换参数见 `assets/MEDIA.md`。这些准备好的 MP4 / M4A 需要随源码保留，普通启动和 Pages 构建不需要 FFmpeg 或原素材磁盘。角色专属视频和其他压缩包未整包加入；三星角色统一使用自身 cutin 与原版 UI 组合演出。

`lib/gacha-assets.json` 列出当前使用的 165 张原版 UI 贴图；所有源 PNG 都已按白名单收纳在 `assets/gacha/`，构建时转换为运行用 WebP。显示屏使用不带文字和彩纸的原始背景，屏幕底色、图标、提示和动态彩纸分层呈现，避免重复 SKIP 和固定彩纸。SKIP、点击手势及结果卡属性徽章均使用原版贴图。发布仅包含清单选定的素材，不附带原录像、抽帧文件、素材压缩包或整个素材目录。素材沿用原游戏美术，其权利不随本项目代码许可证转移。

开发时可打开 `/?gacha-review`，使用内存中的固定初春、食蜂样本对照构图和播放流程，不读取或修改玩家存档；此入口与样本会从正式构建中移除。已实际检查普通卡揭晓、自动返回与图标屏。三星目前使用 cutin 与模糊侧边替代，不新增宽幅素材包；这种近似演出仍与原版宽幅场景有明显差异。

演出使用当前十连 / 单抽的大图预加载，不会在打开首页时下载全部大图。构建产物中的 `gacha/`、`cards/`、`art/` 均按明确的文件清单检查。

## GitHub Pages 发布

独立仓库根目录提供 `.github/workflows/pages.yml`，推送到 `main` 后自动构建，同时支持手动触发。

1. 将试玩源码、锁文件和工作流提交并推送到 GitHub 默认分支。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送 `main`，或在 **Actions → Publish IFfanclub to GitHub Pages → Run workflow** 手动运行。
4. 工作流会执行类型检查、构建与发布白名单核验，并只上传 `dist/client/`。

独立仓库为 `UCCPR/IFfanclub`，默认地址为 `https://uccpr.github.io/IFfanclub/`。构建使用 Pages 返回的 `base_path`。参考 [GitHub 官方自定义 Pages 工作流说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

本地验证仓库子路径（PowerShell）：

```powershell
$env:PAGES_BASE_PATH = '/IFfanclub'
npm run build
npm run preview
# 打开 http://127.0.0.1:4173/IFfanclub/
Remove-Item Env:PAGES_BASE_PATH
```

如更换仓库或自定义域名，更新 `index.html` 中的分享图片绝对网址；工作流部署路径会自动读取 Pages 配置。

## 卡池与规则

`lib/cards.json` 仅包含公开角色字段，来自仓库 `卡牌信息.xlsx` 的 `BattleCard资源`、`AssistCard资源` 两个工作表。卡牌名称保留原始日文，不臆造技能与战斗数值。

更新卡池时，在仓库根目录执行（需要 `openpyxl`）：

```sh
python scripts/export_cards.py PATH_TO_CARD_WORKBOOK.xlsx
```

随后重新运行测试、构建，并提交更新的 JSON。正常网页构建直接使用 JSON，不需要安装 Python。

抽卡规则是本试玩版的独立实现，不调用机器人代码，也不读取 `config.py`：

- 单抽 300 呱太，十连 3,000；十连没有额外二星保底。
- 幻想祭宴与幻想盲盒的基础星级权重为 `72 : 23 : 3`，归一化后约 `73.47% / 23.47% / 3.06%`；期间精选为 `70 : 25 : 5`。
- 三星分组权重按卡池分别为：幻想祭宴 `35 / 30 / 35`、幻想盲盒 `25 / 35 / 40`、期间精选 `10 / 60 / 30`（FES / 期间限定 / 其他），组内等概率。
- 保底定义为连续 149 抽未出 FES 时，第 150 抽必出；任何 FES 三星均清零进度。与旧 Python 计数细节不完全相同，试玩版保证“最多 150 抽”。
- 非保底盲盒有 2% 为黑盒，黑盒 2 / 3 星概率为 65% / 35%。普通盲盒突变：1→2 星 8%、1→3 星 2%、2→3 星 5%。黑盒与突变后角色在对应星级全池等概率抽取。
- 招募扣费、角色入库和盲盒结果一次保存。揭晓只改变可见状态，不重复抽取或扣费。未开完上一轮时禁止继续招募。

## 数据与存档

存档键：`localStorage["ifbot.pages-demo.save.v1"]`。保存内容仅有试玩余额、抽卡记录、持有卡牌、队伍和签到日期。导入文件需要 `format: "ifbot-pages"`、`version: 1`，不兼容 QQ 机器人存档。

每次操作先成功保存，再更新界面。损坏存档不会被自动覆盖，可先下载原始存档，再确认导入或重置。导入时校验文件大小、卡牌 ID、数值、阵容类型和数量。支持 Web Locks 的浏览器会串行处理同源标签页写入；旧浏览器请只打开一个游戏标签页。

清理浏览器网站数据会删除本地存档。跨设备使用需要先导出再导入；不要将个人导出的存档放进源码或 `public/`。

`info/`、`backup/`、`config.py`、`agentmd/` 和现有机器人存档不参与导出、构建或发布。构建只读取公开卡牌 JSON 和白名单原图，发布范围固定为静态输出目录。

公开仓库中的角色图片和角色名称沿用原项目资源，仅用于同人试玩展示；不代表相关素材属于 Apache 2.0 授权或获官方授权。
